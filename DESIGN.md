# Design

This document describes the internal architecture of `nodeip-discovery` and the
reasoning behind its key behaviours. For what the service does and how to run it,
see the [README](README.md); for the development workflow, see
[CONTRIBUTING.md](CONTRIBUTING.md).

## Architecture

The code follows a hexagonal (ports-and-adapters) layout. Business logic depends
only on interfaces (ports); concrete implementations (adapters) are wired in at
the edges through a small dependency-injection container.

```
cmd/                          Entry point, flag parsing, Kubernetes client, ticker loop
  config/                     Environment & build-time configuration
pkg/
  domain/                     Core types (IfaceAddrs) and sentinel errors
  service/                    Ports: InterfaceLister, IPExtracter, NodeAnnotater (+ generated mocks)
  usecase/                    DiscoverNodeIP — orchestrates the ports
  infrastructure/
    interfacelister/          Adapter: enumerates host interfaces via the net package
    ipextracter/              Adapter: filters addresses by CIDR
    nodeannotater/            Adapter: patches the Node annotation
    di/                       Lazy DI container wiring the above together
```

### Layers

- **domain** — Pure data (`IfaceAddrs` bundles an interface's name, flags, and
  addresses) and sentinel errors. No external dependencies.
- **service** — The ports the use case depends on. Each is a single-method
  interface, which keeps adapters small and mocks (generated by `mockery`,
  see [CONTRIBUTING.md](CONTRIBUTING.md)) trivial.
- **usecase** — `DiscoverNodeIP.Execute` ties the ports together:
  `ListInterfaces → ExtractIPs → AnnotateNode`. It contains no I/O.
- **infrastructure** — Concrete adapters and the `di.Container`, which constructs
  dependencies lazily and caches them.

### Discovery flow

```
                 ┌──────────────────┐
  net.Interfaces │ InterfaceLister  │  list node interfaces
        ────────►│   (local)        │
                 └────────┬─────────┘
                          │ []IfaceAddrs
                          ▼
                 ┌──────────────────┐
                 │ IPExtracter      │  keep up, non-loopback IPv4
                 │   (network)      │  addresses inside the CIDRs
                 └────────┬─────────┘
                          │ "ip,ip,ip"
                          ▼
                 ┌──────────────────┐
                 │ NodeAnnotater    │  patch the Node annotation
                 │   (kubernetes)   │
                 └──────────────────┘
```

The loop in `cmd/main.go` runs this use case once at startup and then every
`RESYNC_INTERVAL`. After `MAX_ATTEMPTS` consecutive failures the process exits
non-zero so the orchestrator can restart it.

## Design decisions

### Empty annotation on no match

When no interface address matches the configured CIDRs, discovery does **not**
return an error. It logs the condition and writes an empty annotation value. An
empty result is a legitimate state (the node simply owns no address in those
networks), and surfacing it as an annotation lets consumers distinguish "no
matching IP" from "agent not running" — the latter leaves the annotation absent.

### IPv4 only

CIDRs and the `-exclude-ips` addresses are validated as IPv4 at configuration
load time, and the extractor unmaps and skips non-IPv4 addresses. The annotation
models membership in IPv4 load-balancer networks; IPv6 support would be an
additive change to the extractor and the config validation.

### Address filtering

The extractor deliberately drops:

- interfaces that are down or loopback;
- link-local unicast/multicast addresses;
- any non-IPv4 address;
- any address listed in `-exclude-ips`.

The exclude list (validated as IPv4 at configuration load time, like the CIDRs)
is applied before CIDR matching, so a node can advertise a network while holding
back specific addresses within it — for example a shared virtual IP that should
not be attributed to any single node.

Results are deduplicated (a `map[netip.Addr]`) and sorted so the annotation value
is stable across runs — important for the idempotent patch below.

### Idempotent, conflict-tolerant annotation

`AnnotateNode` reads the node first and returns early when the annotation already
holds the computed value, avoiding needless writes and API churn on every resync.
Writes use a strategic-merge patch, which merges the annotation into the existing
node object without sending a `resourceVersion`, so concurrent updates do not
conflict and no retry loop is needed. A missing node is treated as a
reconciliation failure.

### Interface listing is resilient

`ListInterfaces` fails only if the host interface list itself cannot be obtained.
If a single interface's addresses cannot be read, it is logged and skipped so one
bad interface does not abort the whole discovery cycle.
